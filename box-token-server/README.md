# box-token-server

Готовый к запуску token-exchange сервер для провайдера **Box**
плагина `grapesjs-cloud-assets`.

## Нужен ли он вам вообще?

Только если вы хотите включить `BoxProvider`. Box, в отличие от
Dropbox/Google Drive/OneDrive, требует секрет приложения
(`client_secret`) при КАЖДОМ обмене токена — и при первом входе, и при
каждом последующем автообновлении — а хранить такой секрет в
браузерном коде небезопасно (см. раздел "Box" в `README.md` плагина,
на уровень выше). Поэтому у вас есть три варианта:

1. **Использовать этот сервер как есть** — самый быстрый путь, если
   у вас уже есть где его запустить (свой хостинг/VPS/Node-процесс
   рядом с сайтом).
2. **Реализовать тот же контракт на своей инфраструктуре** (на PHP,
   Python, .NET — на чём угодно) — этот файл `server.js` тогда просто
   референс, что именно должен делать эндпоинт (см. "Контракт
   эндпоинта" ниже).
3. **Не подключать Box вообще** — просто не передавайте `BoxProvider`
   в опции плагина. Остальные три провайдера (Dropbox, Google Drive,
   OneDrive) и S3 от этого сервера не зависят и работают без него.

## Запуск

Требуется Node.js 18 или новее (используется встроенный `fetch`).

**Windows** — дважды кликните `start.bat` (или запустите его из
командной строки в этой папке).

**macOS/Linux** — `./start.sh` (при необходимости `chmod +x start.sh`
один раз).

Скрипт сам:
1. При первом запуске создаст `.env` из `.env.example` и остановится
   с просьбой заполнить его — откройте `.env` и впишите `BOX_CLIENT_ID`
   и `BOX_CLIENT_SECRET` из [Box Developer Console](https://app.box.com/developers/console)
   (ваше приложение → Configuration → OAuth 2.0 Credentials).
2. Запустите скрипт ещё раз — он поставит зависимости (`npm install`)
   и запустит сервер (`npm start`).

Либо вручную, без скриптов:

```bash
cp .env.example .env   # затем заполните .env
npm install
npm start
```

По умолчанию сервер слушает `http://localhost:8787/api/box-token`.

## Подключение к плагину

```js
import { BoxProvider } from 'grapesjs-cloud-assets';

const box = new BoxProvider({
  tokenEndpoint: 'http://localhost:8787/api/box-token', // или адрес вашего деплоя
});
```

Client ID (не секрет) по-прежнему вводится через мастер настройки в
самом UI плагина — сервер тут нужен только для обмена
`code`/`refresh_token` на реальный access-токен.

## Продакшен

- Разверните этот сервер там же, где остальной бэкенд сайта (или
  отдельным маленьким процессом/контейнером) — он не обязан жить
  на том же порту/хосте, что и сам сайт, ему просто нужен HTTPS-адрес,
  доступный из браузера посетителя.
- В `.env` замените `ALLOWED_ORIGIN=*` на настоящий origin(ы) вашего
  сайта (через запятую, если их несколько) — `*` удобен только для
  локальной разработки.
- Держите `.env` вне git/публичного репозитория (уже добавлено в
  `.gitignore` в этой папке) — в нём секрет вашего приложения Box.
- `PORT` можно поменять в `.env`, если 8787 уже занят.

## Контракт эндпоинта

Если вы реализуете этот сервер на своей инфраструктуре вместо
`server.js` — вот что именно ожидает `BoxProvider` (см.
`src/providers/box/BoxProvider.ts`, метод `exchangeToken()`):

- `POST` на URL из опции `tokenEndpoint`, `Content-Type: application/json`.
- Тело запроса — одно из:
  - `{ "grant_type": "authorization_code", "code": "...", "redirect_uri": "..." }`
  - `{ "grant_type": "refresh_token", "refresh_token": "..." }`
- Сервер добавляет `client_id`/`client_secret` своего приложения Box
  и форвардит запрос (как `application/x-www-form-urlencoded`) на
  `https://api.box.com/oauth2/token`.
- Ответ Box (и статус-код, и JSON-тело) пробрасывается обратно как
  есть — при успехе это `{ access_token, refresh_token, expires_in, ... }`,
  при ошибке — собственный формат ошибки Box. `BoxProvider` сам
  разбирает оба случая по коду статуса ответа.
